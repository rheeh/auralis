# 提示词与 TTS 表演审核

审核日期：2026-09-11。范围：当前生产调用链、提示词管理、最近项目实际绑定的 TTS、官方调用协议，以及情绪过度表现的修正。此次没有调用云端 LLM/TTS，没有重新生成已有项目音频。

> 后续更新：已放宽旁白规则，并实现发音词表、相邻台词上下文与生成记录。以下审核保留当时结论；现行使用方式和能力边界见[配音设定与排查](../speech-direction.md)。

## 1. 结论

需要改进的是“如何把剧本意图转换为模型实际能执行的声音控制”，不能只把“强烈”改为“微弱”。当前实现有标签强度丢失、情绪与音量混用、否定指导误匹配等确定问题；这些已修正。Qwen-Audio 原生指导的听感收益仍需实际对照试听，不能由单元测试推断。

本机提示词管理中确实只有一个“默认拆分台词提示词”。但当前工作台分别使用原文解析、人物草稿、台本生成、独立审查和制作助手提示词；数据库模板主要服务旧拆分入口。最近的「0907」虽然项目默认 TTS 为 Edge，人物绑定音色实际指向 `qwen-audio-3.0-tts-plus`。判断模型应看实际角色音色的提供商。

证据入口：[提示词](../../SonicVale/app/core/prompts.py)、[原文解析](../../SonicVale/app/services/source_parser_service.py)、[台本生成](../../SonicVale/app/services/script_draft_service.py)、[旧模板组装](../../SonicVale/app/services/chapter_service.py)、[逐句配音路由](../../SonicVale/app/services/line_service.py)。

## 2. 已确认的问题及修正

| 问题 | 修改前的行为 | 本次修正 |
| --- | --- | --- |
| 原生指令过于抽象 | 拼接“情绪：害怕。情绪强度：微弱”，模型仍可能把情绪类别当成主指令 | 日常表演默认使用交谈音域、局部重音、句尾收束等具体指导；中等及以下不直接重复分类情绪名，保留单句声音指导 |
| CosyVoice 固定情绪丢失强度 | 微弱、稍弱的害怕也映射成 `fearful` | 这两档降为 `neutral`，保留能映射的具体韵律；较高强度继续支持分类情绪，明确的官方格式指令保留 |
| 强度被当作音量 | CosyVoice 强度越高音量越高，甚至覆盖“小声”；Edge 也从情绪推音量 | 情绪强度不再改变音量；只有明确的轻声、大声等发声指导才调音量 |
| 否定指导反向生效 | “不要大声”包含“大声”，“不要放慢”包含“放慢” | 参数适配跳过含否定的分句；原生模型仍收到原始指导。这里只是保守关键词识别，不声称理解任意自然语言 |
| Edge 变化幅度过大 | “稍慢”可直接触发整句 -20% 语速 | 默认情绪映射减弱，“稍慢”改为 -6%；平静且无指导时保持原始韵律 |
| 台本标签缺少依据 | 心理倾向容易直接变成强外露表演 | 区分心理情绪和实际外露程度，普通问答默认低强度；强烈表演须有原文或用户依据，指导聚焦说话目的与一处可听变化 |
| 审查/返修缺少用户风格要求 | 初稿收到用户要求，但独立审查和返修不直接收到 | 原始改编要求和本轮反馈传入审查、返修及最终复核 |
| 模板示例与说话人规则矛盾 | 示例把同一人的原作发言改为新增人物提问 | 内置示例保留原说话人，降低无依据的情绪升级 |

核心代码：[指导编译](../../SonicVale/app/core/tts_guidance.py)、[模型请求适配](../../SonicVale/app/core/tts_engine.py)、[工作流](../../SonicVale/app/services/drama_workflow_service.py)、[独立审查](../../SonicVale/app/services/script_review_service.py)。

新指导示例：把“害怕 / 微弱”作为台本元数据保留；送入原生 TTS 的基础指导为“按日常交谈回应，音量和音高保持平稳，只在一个关键词上轻微着力，句尾自然收住”，随后附上单句具体要求。具体要求优先；剧情明确需要的喊叫、哭笑仍可表达。

这些强弱档位是本项目的保守策略，尚不是经过听感标定的模型参数。对低强度且没有具体指导的句子，当前主动退回自然交谈基线，可能减弱原本想表达的细腻情绪。

## 3. 官方文档核对与模型差异

| 模型/音色 | 官方接口与限制 | 当前项目处理 |
| --- | --- | --- |
| Qwen-Audio 3.0 Plus / Flash | HTTP `input.instruction`；系统和复刻音色支持自然语言指导 | 保留正确字段和端点，使用具体表演提示；不把旧八维向量塞进请求 |
| Qwen3-TTS-Instruct-Flash | HTTP `input.instructions`；支持 `optimize_instructions` | 明确默认 `false`，保留用户主动开启的设置；这是固定官方默认行为，不是已证明该开关会导致过度表演 |
| Qwen3-TTS 基础型号 | 不支持该系列的 Instruct 指令功能 | 不发送不支持的表演字段 |
| CosyVoice v3 指定系统音色 | 如 `longanyang` 接受严格格式、固定情绪枚举；不同音色能力不同 | 微弱/稍弱用中性枚举，不假设存在连续情绪强度旋钮 |
| CosyVoice v3-flash 复刻、v3.5 复刻/设计 | 支持自由指令；文档规定 100 加权字符，汉字计 2 | 使用精简指导；超长时保留完整分句，首个分句已超限则报错要求缩短 |
| CosyVoice v1/v2、无表演指令的音色 | 不能套用上述自由表演指令 | 只做有限的整句参数映射 |
| Edge-TTS | 库提供 rate、pitch、volume，不提供自由表演提示词入口 | 小幅近似映射；不把能力等同于原生情绪理解 |

Qwen-Audio 的字段、正常倍率和自定义发音见[阿里云 HTTP API](https://help.aliyun.com/zh/model-studio/cosyvoice-tts-http-api)；Qwen3 的指令字段及重写开关见[Qwen-TTS API](https://help.aliyun.com/zh/model-studio/qwen-tts-api)。CosyVoice 的能力和长度限制见[非实时语音合成指南](https://help.aliyun.com/zh/model-studio/non-realtime-tts-user-guide)，固定格式须逐音色查[音色列表](https://help.aliyun.com/zh/model-studio/cosyvoice-voice-list)。Edge 的限制依据[edge-tts 维护者文档](https://github.com/rany2/edge-tts)，不能用 Azure Speech 的能力代替该库的能力。

Qwen-Audio Plus 和 Flash 在本次核查中使用相同类别的指令协议。没有证据支持凭型号名称虚构两套“最佳表演参数”；后续应按“模型 + 音色”分别试听标定。

## 4. 不同小说如何使用不同提示词

建议采用“共同事实与格式规范 + 项目风格 + 场景/人物意图 + 模型适配”。不需要为每本小说复制整套提示词，但必须允许风格和节奏变化。

| 题材或场景 | 调整重点 | 应避免的自动推断 |
| --- | --- | --- |
| 都市日常、情感 | 接话关系、潜台词、局部重音 | 亲切就发笑，关心就气声 |
| 悬疑、惊悚 | 证据顺序、信息差、停顿 | 每人每句都害怕、颤音、耳语 |
| 喜剧 | 反差和包袱前后的节奏 | 每句用夸张语气或插入笑声 |
| 动作、幻想 | 行动因果、人物声线辨识、动态层次 | 全程喊叫，情绪持续满格 |
| 文学独白 | 视角、叙述价值、语言节奏 | 为压低旁白比例硬造对白 |

本次已把题材与场景指导加入共享规则，沿用原文输入中的“改编要求”；没有新增类型选择器或独立项目风格配置。

现有旁白规则仍是提示词目标 15%、程序在超过 18% 时报告问题；不允许连续两条旁白。这更接近以对白为主的广播剧，不适合所有有声叙事。后续应由项目制作模式决定比例，不能只靠追加一句题材提示来抵消硬阈值。实现见 [旁白预检](../../SonicVale/app/services/script_draft_service.py)。

## 5. 其他优化建议（尚未实施）

按对成片质量的直接影响排序：

1. **先建立音频对照验收。** 同一文本、同一音色比较无指导、旧指导、新指导；覆盖普通问答、潜台词、克制情绪和真正爆发。核对漏字/多字、发音、声线稳定、表演适度及相邻句连贯。人工盲听决定自然度，ASR 可协助找文本偏差，但不能证明情绪正确。现有[音频审核](../../SonicVale/app/services/audio_task_service.py)主要记录用户通过/退回，不是自动听感判定。
2. **把发音准确与情绪适度分开。** 人名、多音字、数字、英文应有项目词表；Qwen-Audio 已有 `hot_fix.pronunciation` 和 `language_hints` 等官方入口，后端可透传，尚缺项目级词表管理。[官方参数说明](https://help.aliyun.com/zh/model-studio/cosyvoice-tts-http-api)支持这些用途。当前 `clean_tts_text` 会删除所有空格，英文词间边界也会丢失，需单独修正并验证混合语言文本。
3. **补足逐句生成的上下文。** 目前实际 TTS 请求主要包含当前台词与当前指导。可将上一句意图、人物关系、当前场景的交谈方式压缩成非朗读指导；短句优先按对话段做试听，避免每句重新起势。能否使用更长上下文，应按模型协议验证，不能直接把前后对白放进朗读正文。
4. **把声音指导变成少量可编辑控制。** 区分说话目的、外露程度、重音/节奏、发声方式；减少“俏皮、紧张、压低、气声、上扬”等堆叠。现有自由文本框继续保留，但应显示模型实际会执行、近似处理或忽略哪些要求。
5. **统一提示词管理与生成记录。** 界面模板和工作流内置提示词目前并非同一个管理入口。应展示实际生效版本，并在每个 take 保存模型、音色、最终指导、参数与版本，帮助回答“改了哪里，哪次更好”。当前版本记录保留了台词、备注、标签与音色 ID，尚不足以完整还原提供商配置变化。

项目已有[提示词对照实验](../../evals/audio_drama_v2/REPORT.md)，但历史报告明确样本不完整、未进行独立听众盲听，不能据此宣布某种提示词或 TTS 模型最佳。

## 6. 验证与生效范围

- `./scripts/verify.sh` 通过：136 项后端测试、21 项前端测试，包含构建、API、音频导出和时间线流程检查。
- 新回归检查核对实际请求组装：Qwen-Audio 的纯净文本/单数指令字段、低强度指导、CosyVoice 音色能力与中性降级、否定分句、音量解耦、指令长度，以及用户要求经过审查/返修后的保留。
- 测试使用隔离数据和模拟提供商；本次未运行真实云端生成、模型对照或听众盲听，没有可报告的音质提升比例。
- 未修改现有项目的台词、数据库模板、角色绑定或音频。共享规则会在生成/旧模板运行组装时生效，因此不需要覆盖用户保存的模板。TTS 适配对之后的逐句生成生效。
- 若当前后端已运行，需重启后端以载入代码；已有录音不会随提示词变化。选择少量代表句重新生成后，可使用现有音频版本功能与旧 take 比较。
- 固定情绪降级会牺牲部分细微表达；CosyVoice 超长指导的尾部分句仍可能被舍弃；Edge/CosyVoice 参数适配仍是保守关键词规则。这些限制不等同于已完成模型听感标定。
