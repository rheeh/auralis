## 0. 目标与执行方式

将 Auralis 收口为本地优先、单用户、短篇/单章可演示的 AI 广播剧工作台。保持“小说原文 → 人物确认 → 台本生成与审查 → 台本确认 → 正式逐句制作 → 配音版本 → 声音编排 → 成片”的现有产品主线。

本轮优先级是：保护用户已完成的制作、让状态真实一致、使失败可恢复、让代码的职责与依赖可理解。不是扩建商业平台，不是展示技术栈数量。

### 执行规则

1. 先读当前仓库已有 AGENTS/开发约定，检查 `git status`、分支和 HEAD。本任务书是审阅基线，不可覆盖用户的更新；HEAD 不同时先核对差异并更新问题状态。
2. 先建立可运行基线，随后按第 12 节逐批实施。不要仅输出另一个计划后结束；可以安全执行时，继续修改和验证。每批只解决一个可验收主题。
3. 已确认静态缺口先写失败测试；尚未运行验证的风险，先复现。已修好的问题记录“当前版本已解决”，不能为迎合任务书重造修改。
4. 所有自动测试使用临时配置目录、临时数据库和临时音频；禁止接触用户真实 `.local-data`、历史工程和密钥。测试默认禁止外部模型网络请求。
5. 不调用真实 LLM/TTS，不上传小说、音频、参考声音，不运行有付费可能的 eval/seed 生成脚本。真实调用需要用户另行授权，且必须继续遵守当前项目的模型允许/禁止策略，不能自动换模型。
6. 不执行 `git reset --hard`、破坏性 `git clean`，不强推，不推送、不部署、不发布。局部提交前检查 diff，只暂存本批文件，不捎带用户原有修改。
7. 不修改已有音频文件内容，不删除历史 take，不改数据库/项目默认保存位置；备份和迁移也先在副本中验证。
8. 不把“所有问题一次交代清楚”理解成“一次大范围重写”。批次未完成时准确列出剩余项，不能用假实现、吞异常、删除测试来制造全绿。
9. 目标目录是职责边界，不是必须创建的文件清单。没有实现需求，不创建空目录、接口、工厂或占位类。

### 明确不做

保留 Vue 3、FastAPI、SQLAlchemy、SQLite、FFmpeg 和现有本地任务执行方式；不迁移 React，不强制全量 TypeScript，不替换 LangGraph/Agents SDK，不拆微服务，不引入 Redis/Celery/Kafka、通用插件框架、账号/支付/多人协作/RAG/长期记忆。浏览器本地工作台是验收主路径；桌面壳修正现有边界，不扩建全平台安装分发工程。

## 2. 目标架构与依赖方向

### 后端：保留模块化单体，按职责归组

```text
SonicVale/app/
  main.py                     # 应用入口、路由注册；不放制作业务
  bootstrap.py                # 生命周期、迁移、默认数据、运行时启动/关闭
  core/                       # 配置、通用错误等小型跨模块基础
  db/                         # engine/session 工厂与版本化迁移
  models/                     # ORM；本轮不必拆完 po.py，也不改表名
  dto/                        # 公共输入/输出、明确的内部值对象
  entity/                     # 旧 dataclass 兼容；不继续机械增加三份同构模型
  repositories/               # 数据查询/持久化；新热路径不自行 commit
  routers/
    dependencies.py           # HTTP 依赖包装，调用 services/factory.py
    ...                       # 保留现有 URL，校验请求并转换响应
  workflows/drama/            # 工作流结构定义/表演数据约束；沿用有效实现
  services/
    factory.py                # HTTP、worker、脚本共用的轻量组装点
    adaptation/               # parse/roles/draft/review/workflow/commit
    assistant/                # agent 循环、工具 schema、目录、工具处理器
    production/               # 台词/角色命令、版本选择、状态失效
    speech/                   # 配音路由、准备快照、上下文与 trace
    timeline/                 # 时间线构建、编辑、渲染业务
    assets/                   # 素材管理和资源生命周期
    ...                       # 低风险模块只在有收益时归组
  integrations/
    llm/                      # 现有 LLM 传输适配
    tts/                      # 现有 Edge/Cloud/Legacy 传输适配
    audio/                    # FFmpeg、探测和文件处理
  runtime/                    # 任务调度、worker、中断恢复
```

本轮优先拆 `LineService` 的混合职责、共用修改规则和 worker 的 Session 边界。不是先把全部文件移动到新目录。较小的既有模块可暂留原处，旧 import 路径使用薄 re-export 或门面过渡，不保留两份业务实现。

允许的依赖：HTTP / Agent tools / CLI → 业务命令与查询 → 仓储、纯策略、集成适配器。工作流负责调度业务步骤。供应商适配器只接收已解析的普通数据，不能反向调用 router、业务 service 或读取 ORM。runtime 通过组装点调用服务，不能导入 routers。

不同业务服务的协作必须围绕清晰用例，避免通过对方私有方法或 `getattr(repo, 'db', None)` 猜测依赖。确需共用的纯逻辑下沉至命名明确的模块，例如 `resolve_voice_binding`、`clean_spoken_text`、`compute_generation_fingerprint`，不是堆成 `common.py`。

不增加“每个类一套抽象基类 + 实现 + 工厂”。Pydantic 负责边界数据，ORM 负责持久化；只有确有纯逻辑用途时才增加独立领域值对象。

### 前端：页面薄化，不重新设计视觉

```text
sonicvale-front/src/
  pages/                      # 保留 route 入口；负责布局与功能组合
  features/
    workspace/
      components/             # 台本、配音行、版本、助手区等业务组件
      composables/            # useWorkspaceSession / useDraftConfirmation 等
    production/               # 仅在独立职责形成时拆出
    timeline/                 # 沿用已提取的时间线编辑规则
  api/                        # 唯一 transport 和领域 API 包装
  components/                 # 真正跨功能复用的组件
  utils/                      # 有名称、有测试的纯函数
  workspace/                  # 当前 navigation 等可保持原路径
  demo/                       # mock、fixture、WebAudio demo；不混入真实生成
  router/                     # 路由与兼容跳转
```

不要求创建以上全部目录。先提取逻辑再移动文件；不要为了文件短把完整用例切成大量十行文件。

## 3. P0：统一业务命令、事务和 API 更新语义

### 3.1 收敛写入口

至少收敛这些用例：修改台词/表演指导、变更类型/角色、角色换音色、入队/重试配音、选用音频版本、删除台词、替换章节、更新时间线片段。

页面 API、Agent、兼容 API、脚本都必须调用同一个实现。建议新命令使用明确的参数与返回结果；内部可以复用现有 service，不一定建立新的 CommandBus。

Agent/routers 不允许直接 `setattr(line, ...)` 或 `db.commit()` 绕过这些命令。只读查询可以使用现有查询服务/仓储；无需为每个 SELECT 新建一层。

### 3.2 热路径事务边界

每个短业务命令拥有一个清晰的事务边界。先做所有前置校验，再写相关记录，一起提交台词状态、资产引用和时间线失效信息。仓储默认不再自行提交，只 `flush` 取 ID。

迁移必须按调用链进行，不可全局删除 `commit()`：旧接口通过明确的兼容包装保留原行为，完成迁移后移除包装。注意 SQLAlchemy 已有隐式事务的会话，不能机械嵌套 `with db.begin()` 导致运行时错误。

一次工作流包含多个短事务是合理的：保存阶段/checkpoint → 释放事务 → 调用外部模型 → 用请求 token/版本检查后保存结果。不要跨 LLM/TTS/FFmpeg 长时间持有数据库写事务，更不要把整轮 Agent 外部操作伪装成可原子回滚的数据库事务。

事件的持久化记录与关联业务变更保持一致；网络通知发生在提交后。通知失败不应把已经成功的业务改成失败。现有事件序号可继续使用，不引入消息中间件或通用事件溯源。

### 3.3 DTO 与空值

新增或修正 `LineUpdateDTO` 等受限输入：仅允许可编辑字段，未出现表示不改；明确 `null` 表示清空允许为空的字段。`status`、`is_done`、版本列表、服务器输出路径、内部 request/generation ID 不能由普通台词编辑请求任意写入。

创建、更新、响应、内部 TTS 输入快照不要继续共用一个 `LineCreateDTO`。新增边界用 `extra='forbid'` 或同等严格策略；旧前端先同步更新，兼容 API 的转换需有明确白名单，不静默放行。

校验项目—章节—台词—角色归属。批量排序必须属于同一章节，不能借更新 DTO 改动 `chapter_id`。素材导入与服务器文件路径是专用用例，不通过通用台词 PATCH 处理。

统一新热路径的错误模型与真实 HTTP 状态；过渡期前端统一解析 HTTP 异常以及历史 `{code,message,data}`，避免 HTTP 200 的业务错误被认为成功。保留 API URL，除非给出了兼容映射和回归测试。

## 4. P0：输入、音频与导出的一致性

### 4.1 不再把一个 done 标志当成全部事实

区分至少三个概念：有可播放文件；音频对应哪一版输入；用户当前选用了哪个版本。任务状态代表某次执行，不等于章节生产进度。旧音频即使可以试听，也不代表适用于修改后的台词。

保留 `audio_versions`/`audio_variants` 的现有兼容结构，不要求本轮把所有 JSON 正规化成新表。为记录补充输入指纹和来源关联，统一封装读写；后期版本需能够识别来源 take，避免跨来源误选。

### 4.2 冻结生成输入

用一种明确的数据结构表达已解析的配音请求：台词文本、发声角色、选用音色及供应商/模型、实际路由、指导、情绪与实际强度、发音替换、有效项目设定、参与请求的上下文、能力策略版本和供应商请求参数。

对影响输出的字段计算稳定指纹，不含时间戳、随机 task ID、API key。持久化的是脱敏快照和配置引用，不能持久化可直接使用的密钥。发送时使用这份快照/同一个 builder 的结果，不重新散落地解析一遍当前数据库设置。

涉及上下文时不能只比较本句文字：相邻台词、整场规划、项目表演设定和发音表都可能改变最终请求。按实际依赖计算，或保守标记受影响场景；避免每改一句就使整个项目无条件失效。

### 4.3 条件完成与晚到结果

worker 完成时比较当前输入指纹、任务 attempt/run token 及取消状态。仅当全部匹配时，才把当前输入标为可用并按既有产品规则选用新结果。

不匹配的结果可保留为历史 take，标明来自旧输入，但不得自动覆盖当前选择，不得使当前台词变成 done。重复回调应幂等。

在完整指纹机制完成前，可以临时在前后端共同禁止修改排队/生成中的台词；这只是过渡保护，不能当作最终解决项目级配置变化、重复请求和晚到结果的方案。

### 4.4 失效传播矩阵

| 修改 | 要检查/失效的下游 | 不应该发生 |
| --- | --- | --- |
| 台词文本、角色、类型、顺序 | 当前生成适用性、相关场景规划/上下文、时间线、成片 | 删除旧音频、把旧音频称为新台词 |
| 表演备注、情绪、强度 | 受影响 TTS 请求与相关场景规划，时间线/成片的“符合当前制作”状态 | 仅页面修改有效，助手修改无效 |
| 角色音色/有效模型配置 | 使用该角色/配置的台词请求适用性 | 把绑定新音色等同于旧音频已换声 |
| 项目基调/发音词表 | 实际请求受影响的台词 | 无提示地继续把旧生成视为最新 |
| 选用 take/后期版本 | 相关时间线资产与成片 | 播放版本与导出版本不同 |
| 音效位置、时长、增益、静音 | 时间线与成片 | 没改人声却重新发起 TTS |
| 停用供应商 | 禁止新请求，保留历史试听 | 已有合法文件突然不能播放 |

只对真正改变了生产输入/选用资产的命令失效，不因所有状态更新都重新构建时间线。

统一 UI、批量生成、Agent、readiness 和导出对“需要生成”的判断。文件检查使用统一的选中路径解析器，不只看 `audio_path` 字符串非空。

### 4.5 部分成片与历史版本

继续支持阶段成片，但明确列出缺失/过期的人声和素材，不能静默跳过关键对白仍叫“完整成片”。用户明确选择历史 take 时，展示其对应文本/指导；不得把“我选了旧版本”自动当成“旧版本符合新输入”。可在完成适用性判断前限制不匹配 take 的正式导出，但保留历史试听。

时间线重建保留手工位置、淡入淡出、增益和裁剪。素材长度变化时遵守已有“未裁剪跟随新时长、显式裁剪受源长约束”规则，不能借整理代码改掉既有混音选择。

## 5. P0：覆盖、删除与文件安全

### 5.1 同名不等于同一个章节

新建改编没有目标 `chapter_id` 时，必须创建新章节或提示同名冲突，不能按标题隐式复用并覆盖。UI 的“新建”不得默认发送替换语义。

覆盖必须给定目标章节 ID、期望版本、影响范围，且用户明确确认。覆盖前备份台词、时间线、来源文档和音频引用；校验无活跃任务。旧音频保留，数据库引用按外键约束处理。失败时旧工程可继续打开。

### 5.2 删除规则一致

单句、整章、整项目删除要共用资源生命周期规则，而不是仅单句删除保护充分、批量删除绕过。处理活动任务、时间线锚点、被引用素材、历史生成记录。保留已有软归档/审计能力；是否物理清理作为显式操作，不自动清理用户生成的 take。

### 5.3 不可变生成文件

每个 task/attempt 写入自己唯一的临时文件，验证成功后发布为唯一版本文件，再更新数据库选用引用。不要让失败、取消或晚到线程覆盖共享的 `id_x.wav`。旧 canonical 路径可作为只读兼容入口。

文件系统与数据库不是同一个事务。明确选择顺序和异常恢复：先安全发布独立文件，再提交引用；失败的无引用文件登记为可检查孤儿，不误删已引用文件。混音 WAV 与 manifest 使用同一个冻结快照；并发编辑后不得标成对应新时间线的有效结果。

## 6. P0：工作流、任务、并发和恢复

### 6.1 工作流动作是有前置条件的命令

保留数据库状态机，将阶段、合法动作、重试映射集中定义。HTTP、Agent 和 UI 展示使用相同的状态语义。UI view 与业务 stage 保持分离，不因切换页面改变后端阶段。

幂等键先查已完成/已接收的命令，再做当前阶段判断；同一键不得再次启动相同付费动作。对并发提交进行数据库条件抢占，校验预期 stage/revision 和 lease token；内存中的“先查后写”不作为唯一并发保护。

将 `reviewing_script` 补入恢复路径，并区分初审、返修、复审 checkpoint。失败后使用已保存草稿继续，不重复调用解析和人物生成。最后审查仍不通过时保留人工选择权，但用户确认应明确看到问题；不把模型分数当成真实质量认证。

租约必须有过期处理和结果提交 token 检查，异常也能释放。对长步骤采用有限租期与受控续租，或者足够保守的期限和超时处理；不让旧 worker 用过期租约覆盖新结果。取消需定义可取消范围和供应商调用不能撤回的边界。

### 6.2 本地队列仍可保留

数据库保存任务与 attempt、输入引用、错误和中断状态；内存队列负责本进程调度。可设置有限容量和并发数，但不把当前 `full()` + `put_nowait()` 的检查当成跨线程原子保证。

选用最小本地一致性方案：持久化待调度任务后由调度器拾取，或入队失败后记录明确可恢复状态；跨线程入队应有确认结果，不能只发 `call_soon_threadsafe` 就宣称成功。队列满时不能留下永久 processing。

启动时通过本进程实例标识/旧租约识别遗留执行。把真正遗留的 queued/processing 和改编中阶段标为 interrupted 或兼容的 failed + 专属 error_code；提供从 checkpoint 重试。不要把其他活进程的任务误判遗留，默认单实例启动保护即可，不需支持多实例集群。

重启不得自动重发不确定是否已付费的请求。可以查找已发布、可核对指纹的本地产物；无法确定供应商是否已完成时明确显示不确定并交由用户重试。不能承诺外部服务 exactly-once。

### 6.3 线程与超时

executor 只接收普通不可变数据与受控传输参数，不接收绑定于请求/主线程 Session 的 ORM 对象和 repository/service。需要写 trace 的线程使用自身短 Session；现有 `TTSRequestRecorder` 的独立 Session 设计应保留。

外层超时、UI 停止等待、Future 取消，不代表已运行的底层线程或供应商任务已经停止。为所有供应商 HTTP 调用和 FFmpeg 子进程设置适当超时；底层未结束的线程不能继续写当前选用文件。

以 attempt token + 唯一输出路径隔离晚到结果。对仍在运行的 executor 任务跟踪资源占用，不能在逻辑超时后无限启动新工作。单项失败不会杀死整个 worker 循环；错误处理和通知失败也不得使 worker 永久退出。关闭时停止接收新任务，记录中断，再有界释放资源。

### 6.4 进度语义

章节进度按当前可朗读台词及其有效采用版本统计；历史 attempt 数量另列。不要把历史所有任务简单相加当成当前完成比例。队列页面能区分排队、处理中、已完成、失败、中断和旧输入结果。

## 7. P1：拆解服务，但不重写业务

### 7.1 LineService 的提取顺序

第一步保留原 public 方法，内部委托：台词命令 → 统一校验/失效；音频版本 → 注册/选择/来源；TTS 生成 → 已准备请求执行；FFmpeg/文件转换 → 无 ORM 的适配器。

先提取纯函数和传输代码，再统一修改用例的事务。不要在一个 diff 中同时修改所有文件名、错误码、数据结构和页面调用。

`services/factory.py` 继续作为不依赖 FastAPI 的组装点；router 中的小型 Depends 包装保留，但不能各自构造不同版本依赖。main/bootstrap 与 worker 不依赖 router。

### 7.2 单一配音解析与请求构建

`production_configuration`、`SpeechDirectionService.prepare/preview` 和真正发送请求的代码，应基于同一个解析结果/请求 builder。前端消费后端返回的实际配置和能力，不自己重新猜模型前缀。

解析结果至少包括：供应商、模型、音色、绑定来源、最终 route、指导 mode、实际文本、实际指导、近似映射参数、忽略项/警告和策略版本。预览与实际请求除凭证、时间戳等必要运行字段外一致，用快照测试验证。

把云模型的供应商协议集中到适配器里。网络重试集中在一处并有总尝试/超时预算，避免 LLM engine 的重试与 JSON 结构修复相乘后不可预期；鉴权、额度、模型不允许等错误不触发盲重试或供应商切换。

### 7.3 显式音色字段

新增可空 `provider_voice_id`/`voice_key` 或等价字段用于机器 ID，description 只描述给人看的信息。保留历史 `qwen_voice:`、`cosyvoice_voice:`、`edge_voice:` 的读取兼容；遇歧义不要猜，提示重新绑定。

迁移在数据库副本执行，记录能够可靠解析和无法解析的数量。旧 description 不丢失。不要求重建所有 voice 表，也不强制已有参考音频都变成云端音色。

### 7.4 场景规划与声音事件的执行边界

保留 scene plan 的稳定 ID、证据校验、指纹和 stale 回退。明确生产阶段的旧规划如何恢复：优先沿用当前 fallback，提供仅作用于目标场景的重新审阅/生成能力可作为后续项；不能为了恢复规划覆盖已制作的全章。

盘点 `audioEvents` 类型的真实消费者。目前时间线明确处理 `sound_library_placement`，不能据此认为所有自由文本 timing/break/reverb 都已执行。输出一张事件能力表：自动执行、需要素材绑定/人工编排、仅备注。对未支持事件给出待处理标记。

本轮只统一已实现事件的契约；确有必要可实现窄范围的数值 pause/placement，并补真实时序测试。不要制作任意自然语言音频事件解释器，不能静默忽略却在界面称已完成。

## 8. P1：Agent 的动作契约与受控返修

将大文件拆为：循环/上下文、工具 schema 与目录、工具处理器、结果汇总。保留最多轮数和工具数量等预算，不增加新的 Agent。

每个工具有自己的 Pydantic 参数模型，而非全部依赖 `dict[str,Any]`；必填项、范围、互斥定位条件和项目归属由程序校验。模型只决定调用候选，不能获得任意 SQL、任意文件读写或服务器路径能力。

只读查询不应产生制作写操作；写动作忠实于用户明确请求。歧义、批量生成、覆盖或可能大范围修改的请求先展示范围/数量并确认；明确的小范围编辑可直接执行并给出变更前后。不要为了每句话增加一轮 LLM 权限判断。

逐工具持久化 operation_id、目标、变更前后摘要、结果与错误。第二个工具失败时呈现第一个已成功，保留 UI 刷新动作；不要声称“项目完全没变化”。恢复或重复发送时不重复执行已经成功的同一动作。

定向返修目前不能仅凭提示词“其他不变”承诺最小修改。为目标场景/台词增加修改范围与版本校验；模型只返回目标局部内容时，由程序合并并保持范围外数据不变。需要整章重新改编时，作为明确操作，不静默扩大范围。

保留原文为素材、不执行其中指令的提示约束，同时测试原文/台词中的恶意指令不能绕过工具参数、目标归属和确认规则。无需增加通用安全代理。

## 9. P1：前端状态与组件整理

### 9.1 先提取状态，再移动组件

从 `ProjectWorkspace.vue` 提取：`useWorkspaceSession`（上下文加载）、`useDraftConfirmation`（确认/提交）、`useProductionAssistant`（消息与动作）、`useTaskPolling`（刷新生命周期）。从 `ProductionScriptPanel.vue` 提取台词编辑、播放/音频资源、版本选择和生成动作；时间线复用已有 editing 纯函数。

组件按完整职责拆，例如台词列表/台词编辑器、音色状态、版本选择、助手消息区、播放控制。不要让子组件直接改兄弟组件内部状态；用明确 props/emits 和 composable 方法协作。组件重排不改变用户工作流和现有标签。

### 9.2 一个工作台上下文

所有请求使用 `{projectId, chapterId, sessionId, epoch}` 上下文。切换章节、项目、会话或卸载时取消/忽略旧请求。已有 epoch 保护要扩展到 history、配置、生成任务、台词列表等所有回写，不能只保护第一个请求。

前端区分服务器快照与未保存本地编辑。轮询不得覆盖用户未保存的人物卡/台词；有 dirty 表单时合并状态字段或提示冲突。存在未保存内容时切换章节给出明确选择，不能悄悄丢弃。

`busy` 绑定实际 operation，而不是多个布尔值相互推断。UI 等待超时显示“停止等待，任务可能仍在执行”，恢复后查询真实结果，不立即重复生成。

选择一种主刷新机制。现有轮询足够时先统一轮询；WebSocket 作为增量通知加快刷新即可，不维护两套互不一致的生产状态。组件卸载清理 timer、订阅、播放器、object URL 和事件监听。按 session/operation 去重 UI 动作，不能刷新历史后反复自动播放。

### 9.3 生产信息清晰且真实

统一显示：当前编辑内容、实际配置、当前 take 的来源内容、是否适用、是否生成中、是否需要重新配音。把纯台本视图的编辑职责与配音视图的生成/播放职责分开，避免每个视图都显示所有操作。

保留样片和真实制作两条路径。Demo transport 只实现允许的演示动作，未知/不支持端点返回明确错误，不用通用成功响应伪造生成。文本修改后的预生成音频失效提示继续保留。

前端 API_BASE_URL 来自统一配置，Electron 实际端口与浏览器配置一致。不要用超长全局 HTTP timeout 掩盖异步任务设计；快速命令返回 operation ID，长任务由查询跟踪。

## 10. P1：启动、数据迁移、边界安全

### 启动与健康

`main.py` 负责构建应用和注册；bootstrap/lifespan 负责日志、建表/版本化迁移、默认数据、任务恢复和关闭。不要在普通 import 时依赖当前工作目录或触发生产数据修改；至少做到测试能够先传入临时配置再创建 engine/app。

保留已有版本化迁移机制。开发和测试使用同一个 engine 构造函数，均打开外键；并发测试使用临时文件 SQLite/独立 Session，而不是用单一内存会话冒充多请求。

健康检查确认服务身份、版本、数据库迁移状态、worker 是否启动和 FFmpeg 是否可用，不调用付费模型。不能仅因 8200 上任意服务的 `/docs` 有响应就复用它。UI 提示明确区分“后端未启动”“配置缺失”“供应商请求失败”。

### 迁移与备份

本轮新增字段采取 additive migration：先加可空字段/安全默认值，再回填可证明的数据，旧行可读。运行迁移前在独立目录备份 SQLite（使用数据库一致性备份方式，不能对正在写入的库只随意拷贝主文件）和必要工程元数据；先在副本迁移、跑验收。

不修改历史文件路径或表名，不把 `app_test.db` 仅因名字不好听改名。清理 orphan 先生成只读清单，用户确认后才物理删除。生产 schema 迁移后，git revert 不等于数据库回退：记录兼容范围，必要时停止服务后用验证过的备份恢复。

### 本地安全边界

默认仅回环监听，限制允许的 Origin；WebSocket 同样检查。桌面恢复 webSecurity，保持 contextIsolation/nodeIntegration 的安全方向，收敛 preload 暴露 API、验证 IPC 参数并限制导航/新窗口。sandbox 是否立即启用需根据现有 preload 兼容性验证，不能通过再次关闭所有保护掩盖问题。

不引入账号系统。对跨源到本地服务的风险，可采用本地实例 token/明确请求校验等最小措施，配合配置与桌面路径测试；不能把 CORS 当作完整身份验证。

通用更新端点不能写任意路径；本地导入明确用户选择源文件，校验格式/大小并复制到受管目录；生成/删除文件限制在已登记的工程根目录和资产清单中。供应商自定义地址允许用户主动配置本地服务，不一刀切封禁所有 localhost，但模型/上传内容不能控制目标地址。

trace、日志、错误响应、导出诊断信息均脱敏。已有 TTS redact 逻辑保留并扩展测试，不只在 UI 隐藏 key。API 配置界面可以管理凭证，但普通项目/任务/trace 响应不携带密钥。

### 依赖与历史代码

记录当前实际可运行的 Python/Node/FFmpeg 组合，锁定仍使用宽版本范围的运行依赖或增加 constraints。不要为“最新”升级主版本。测试依赖单独声明；继续用 npm lockfile。

列出活跃入口、兼容入口、无引用文件。先从路由、import、脚本、测试、Electron 构建配置、docs 逐项追踪；只有证明无消费者才删除旧页/旧服务。旧适配 API 若保留，必须走共享写规则。不能仅因旧文件巨大就优先重构它。

保留原有 LICENSE、素材署名与来源；不要为作品集包装删除第三方许可、作者或来源说明。

## 13. 维护文档、效果验证与作品集

### 文档只保留一个当前事实来源

- 一份当前架构说明（可更新并指定现有 `docs/project-map.md` 或架构文档为 canonical）：真实调用链、状态归属、配置、兼容入口、模块图。

### 工程正确性与效果验证分开

Codex 本轮可以完成：冻结小样本、构建评测脚本/评分表、绑定 commit/prompt/schema/policy 版本、记录假模型工程测试。没有用户授权不得跑真实模型，也不得自行填写听感得分。

## 14. 收工标准

本轮完成的定义不是“目录漂亮”或“文件数量变少”，而是：同一业务只有一个权威写入实现；状态/资产/配置有明确归属；旧结果不会冒充新结果；重复/失败/中断不会破坏工程；前端切换不会串数据；测试和迁移可以复现；公开演示不夸大实时能力或效果证据。

满足以上标准后停止架构扩张。更换框架、全量规范化数据库、复杂专业后期、更多供应商或 Agent，均不属于本轮完成条件。
